基础已具备，内容覆盖与证据建设成为重点

先说明需要补什么内容，以及每类内容解决的用户问题。

结论：下一阶段需要持续补充有证据的高价值内容

抓取与正文读取基础已具备。对标 Channel3，首页评分 73 vs 75、段落可引用性均分 37 vs 38，差距更明显地体现在内容覆盖：CommerceAI 17 个页面，对方已布局博客、比较内容、垂类 API 及大量数据页。应优先补齐 API 选型、技术接入、实际使用与可信证据，再按验证结果扩展内容。

项目方确认基础优化已完成。2026-11-17 报告显示：27 个 AI 爬虫获放行，CDN 未拦截，17 页无需执行 JS 即可读取完整正文；新版对标仍发现软 404、文档 Schema 等收尾项，应与最新上线状态核对。

具体补这五类内容

先做前四类；第五类在具备真实数据、验证需求后小规模试点。

内容类型具体建设内容为什么补 / 怎么算补到位
01 · 产品与 API 页面Shopping API、Product Search API、MCP 等独立页面，说明功能、覆盖、时效、计费、限制与请求/响应示例。承接明确的产品需求。用户能看懂是否适用，并进入 Try API / Connect MCP；每页聚焦一个主要任务。
02 · 选型与比较内容CommerceAI vs Channel3 / SerpApi / 其他适用方案，以及商品数据 API 选型指南和客观能力矩阵。覆盖“该选谁、为什么选”的决策问题。比较维度与依据清楚，写明适用条件和限制，能够核验。
03 · 教程与实测案例从首次请求到完整 AI Shopping Agent 的接入教程，包含 MCP 配置、代码、真实返回、错误处理与完整流程。把产品主张变成可验证的使用证据。示例可复现，有测试日期、条件、结果和技术审核人。
04 · 品牌事实与可信引用产品定义、FAQ、About、数据来源/更新说明；相关开发者媒体的独立教程、评测和第三方榜单。帮助用户与 AI 准确识别和验证品牌。事实与来源一致，内容能独立回答问题，站外发布有真实链接。
05 · 垂类与数据页试点先选少量有需求的服装/美妆/电子等场景，以及品牌/类目数据页，提供真实统计、差异化说明和调用示例。扩展长尾需求覆盖。每页有独立价值，验证抓取/索引、真实提及/引用后再扩量；按有效覆盖衡量。
内容质量的共同标准：明确回答用户问题，具备真实数据或示例、来源、更新日期、适用边界、相关内链和产品 CTA。既看覆盖多少高价值问题，也看答案是否可信、能否继续操作。
展开 Benchmark 与技术收尾依据

Benchmark · Channel3 · 2026-11-17

单页指标接近，内容覆盖差距更明显

来源为内部对标报告：同工具、同版本、同参数；CommerceAI 已校正软 404 导致的每页 2 分虚高。

73 vs 75首页 GEO 评分9 个维度中 8 个相同；差异集中在品牌实体。为工具就绪度评分。
37 vs 38段落可引用性均分双方均分接近，但样本结构不同；不足以证明两站整体质量相同。
17 vs ≈30,850报告列示的可收录页面量后者主要是程序化数据页；页面数量不等于已被 Google 收录或被 AI 引用。
54.4 vs 65.8文档平均评分双方各 13 页；文档是可比页面中差距较大的一类，需补 Schema、日期等。

Channel3 已有、我们尚缺的内容类型

  • 博客：30 篇，GEO 评分平均 85.5；其中 8 篇为“Channel3 vs X”比较内容，另有商品数据 API 榜单。
  • 垂类 API 落地页：15 页，覆盖服装、美妆、电子产品等使用场景。
  • 程序化数据页：30,587 页，覆盖品牌、类目和零售商；本次只抽样 30 页。
  • 业务含义：对方有更多内容承接不同问题。建议我们先补 API 选型、比较和开发者实测，再按需求扩展垂类及数据页。

质量提升机会：两边都缺原创信息

  • 统计密度均分：CommerceAI 0.7/15、Channel3 1.0/15；独特性：0.4/10 vs 0.3/10。
  • Channel3 垂类 API 页虽有技术分，45 个抽取段落的可引用性评级全部为 F；数据页段落平均也仅约 29–38 分。
  • 建设方向：用真实 API 返回、字段覆盖、相关性/价格时效实测、完整调用过程和明确限制，形成可核验的原创答案。
  • 扩量原则：先做少量高需求、有独立数据和说明的品牌/类目页，验证收录与引用后再扩展。

新版同时校正了技术状态与比较边界

  • 评分勘误：不存在路径返回首页 200，导致根目录 /llms-full.txt 和 /.well-known/ai.txt 被误判存在。首页由 75 修正为 73，全站平均由 59.5 修正为约 57.5，docs 平均由 56.4 修正为 54.4；这是评分校正，并非性能退步。llms 维度实际 5/6，AI 端点维度实际 0/3。
  • 技术收尾：抓取正文基础已具备；新版仍记录软 404、文档 Schema/日期/独立描述、About 与 sameAs 等项。应对照最新上线状态补齐与复测，不宜写成所有技术项均已清零。
  • 样本限制：Channel3 审计 111 页（98 个 sitemap 页 + 13 个文档页）；段落比较为 CommerceAI 91 段 vs Channel3 475 段，后者不含文档，因 Mintlify 解析受限。不可直接外推至两站全部内容。
  • 结果边界：85.5 等分数衡量技术/内容就绪度，未证明真实引用增长。双方 Wikipedia/Wikidata 均无匹配实体，报告已人工纠正工具的撞名误报。

数据与方法见 Channel3 对标报告 ↗。此处复述报告结果，未重新独立审计两个网站。

02 · Delivery & resourcing

内容怎么补：执行方式与人力投入

围绕同一份内容清单，比较 Agency 与内部自建的分工、投入、周期和成本。

两种方式都需要内部提供真实产品证据

有 Agency 时，外部承担策划、英文编辑、生产与渠道执行，内部负责事实、审核和上线；内部自建时，需要补上固定内容 owner、英文技术写作工时和持续分发能力。

比较项A · 有 Agency 服务B · 无 Agency，内部自建
买什么 / 建什么采购问题研究、英文编辑与内容生产、发布协同、信源拓展和月度运营；内部保留产品事实、技术审核与验收。指定内容负责人，搭建选题 → 实测 → 撰写 → 审核 → 发布 → 评估的固定流程，形成自己的内容能力。
SEO 怎么做Agency 做词页映射、页面简报、文章与内链规划；内部提供真实示例并完成网站上线。内部增长负责人排词与页面优先级，技术写作者建设 API/MCP、比较、教程和场景页面，工程负责上线。
GEO 怎么做Agency 将 Prompt 缺口转成内容与信源计划；内部现有评估与 agency 监测对齐口径，验证真实提及和引用。用已有评估做缺口分析，内部写清产品事实与完整答案；由负责人推进开发者社区和第三方教程合作。
内部投入建议约 0.4–0.7 FTE：项目负责人 0.2–0.3；产品/技术审核 0.1–0.2；工程上线 0.1–0.2。仍需持续参与。约 1.4–2.2 FTE：增长负责人 0.3–0.5；技术内容写作者 0.8–1.2；产品/技术审核 0.2–0.3；工程 0.1–0.2。角色可兼任，但工时需锁定。
六个月费用原报价 GEO $45,000、SEO ¥129,000，均为六个月；包价待按新增范围修订。另计内部工时与未包含的工具、媒体费用。内部投入工时成本 + 模型/API 与必要工具 + 经批准的内容合作费用。已有工具与评估直接复用。
启动条件服务范围、编辑能力、交付样稿、客户审核权与合同 KPI 确认后启动；采购周期需单独排期。指定 owner、安排英文技术写作能力、每周技术审核窗口和发布支持后启动；若需招聘，周期另算。
主要依赖内部资料与审核速度、agency 的产品理解和内容质量、可核验的信源执行能力。人员工时是否可持续、英文内容质量、跨角色协同与第三方渠道拓展能力。

人力为规划估算：FTE 表示全职等效工时，需按实际资源与试产结果校准；不含产品功能研发。

A · 有 Agency：具体服务、内部职责与交付

Path A · Agency

有 Agency：外部负责内容执行，内部控制事实与质量

把 agency 服务重心明确落到内容与信源新增交付；技术收尾单列，复用现有评估。

采购范围

  • SEO：关键词到页面映射、API/场景页面简报、比较文章、开发者教程、内链与页面内容优化。
  • GEO：Prompt 到内容缺口映射、产品事实整理、可引用答案、第三方教程/评测和信源拓展。
  • 运营：月度内容排期、编辑、审核返工、发布清单和效果复盘；原稿、素材、URL 与数据可交接。

内部仍需负责

  • 确定目标用户、产品定位、优先主题与业务转化口径。
  • 提供真实请求/响应、可披露的产品数据、竞品比较依据和使用限制。
  • 技术/产品审核、网站代码修改与上线；agency 的“优化建议”和“实际开发”需明确边界。
  • 复用内部评估并审核发布渠道、媒体费用与内容事实。

交付与合同

  • 先评审 API 页和实测教程样稿，再确认规模化排期。
  • 文章、页面更新和发布渠道分别计数，写明语言、证据要求、修改轮次与验收方式。
  • 保留 GEO 可见度合同 KPI；真实引用、SEO 表现和产品激活分开记录。
  • 原方案内容数量、外链数量与税费/币种差异，按后文报价事项澄清。
适合条件：可以安排内部审核和上线，但缺持续英文内容产能；agency 能提供可复现、有产品深度的样稿，并接受按新增资产与效果透明验收。
B · 内部自建：人员安排与每周生产流程

Path B · In-house

无 Agency：把内部评估变成每周内容生产流程

已有技术和评估能力是起点；需要补足固定内容 owner、英文技术写作与持续分发的责任人。

人员怎么安排

  • 增长/内容 owner：负责主题优先级、词页映射、排期、渠道沟通和结果复盘，对产出节奏负责。
  • 技术写作者：负责英文页面、教程和比较内容；AI 辅助提纲、初稿与改写，产品事实由人审核。
  • 产品/技术专家：提供可运行示例与原始数据，审核能力主张、实测方法和适用边界。
  • 工程支持：处理技术收尾、发布模板、内链、埋点与上线；不把所有写作工作转给工程。

每周怎么运行

  • 周初：结合搜索需求与固定 Prompt 表现，选 1–2 个高价值问题，明确目标页面和 CTA。
  • 周中：实测 API/集成流程，保存请求、响应、日期和条件；撰写答案、教程、比较或案例。
  • 发布前：做事实、代码、英文表达、来源、结构化数据与内链审核，再上线。
  • 发布后：登记 URL、内容版本、发布日；检查抓取/索引，按月复测搜索与 AI 表现并更新内容。

内容库

维护产品事实、原始实测证据、主题/问题/URL 映射、文章模板与变更记录；所有页面追溯到审核人。

评估与数据

复用现有技术与可引用性 benchmark，补固定问题的真实提及/引用实测；GSC、GA4 与产品事件共同跟踪。

站外与渠道

owner 维护相关开发者媒体、社区和独立教程作者清单，记录合作方式、费用、发布链接和后续引用；拓展速度需纳入排期。

适合条件：能稳定安排专职或等效技术内容写作工时，产品专家愿意按周提供证据并审核，且有人负责渠道分发与月度复盘。

A common six-month plan

用相同交付目标，比较两种执行方式

以下为启动后的建议计划，采购、招聘或人员未到位的等待时间需另算。内容量是规划目标，需按试产结果校准。

第 1–2 周

A · Agency 对齐与试稿

交接技术与 benchmark，确认范围与合同口径；agency 出选题与样稿，内部给数据、审核和上线支持。

B · 内部建流程

落实 owner、写作和审核工时；建立证据库、模板、发布清单与目标问题集，完成首份样稿。

第 3–8 周

A · 持续交付与审核

按排期生产并修订首批内容，提交信源清单、发布记录；内部按同一质量门槛验收。

B · 每周生产与发布

按固定节奏完成实测、英文编辑、技术审核和上线；由内部 owner 直接推进第三方沟通。

第 3–6 月

A · 外部扩充，内部验收

围绕有效主题扩大内容与信源覆盖；每月复盘交付、真实提及/引用与搜索/产品事件，按合同评估。

B · 内部扩充与迭代

复用验证有效的模板，持续更新证据、比较与教程；选择少量有数据的品牌/类目页试点，再决定扩量。

共同产出目标：先验证质量与节奏，再扩大规模

  • 前八周试点：建议上线 6–8 个新增或实质重写的高意图内容资产，优先 API/MCP 商业页、可复现教程、比较/选型内容与带证据的案例；新增和更新分别记录。
  • 六个月规划：建议累计 24–36 个经审核的重点资产，按首批生产工时与质量再校准；这是本稿建议服务范围，区别于原 agency 方案中的 36–42 / 150 数量口径。
  • 发布标准：每个资产有目标问题、事实与证据、适用边界、审核人、更新日期、相关内链与产品 CTA；相同内容的多渠道转载不算新增独立资产。
  • 复盘标准：交付质量与节奏 → 抓取/索引 → 固定 Prompt 的真实提及/引用 → 产品动作；八周先判断执行可行性，SEO 持续效果按六个月观察。

  • 外链数量与质量：报价页列有约 180 条、DA45+ 的综合外链建设项；请确认 DA 的定义、域名去重、主题相关性、落地页面、是否包含媒体/发布成本及双方审核权。
  • 合并报价：要求分别列 SEO、GEO、共享内容/技术资产、媒体或 PR 代投费用；共享部分只计费一次，同时提供单买价、合并包价、月度/一次性费用和超范围单价。
  • 币种与合同总额：GEO 报价页使用 $，具体币种待正式确认；SEO 使用 ¥；先确认计价币种、汇率/付款安排、税费和最终包价，避免直接把两项数字相加当作合并合同金额。

Decision proposal

建议先做八周自建试点，同时拿到可比较的 Agency 报价

考虑已有技术与评估基础，先验证内部能否稳定产出；是否采用此路径，取决于能否锁定写作与审核工时。

能落实内部产能 → 自建

启动前指定 owner，并承诺约 1.4–2.2 FTE 总工时。前八周用 6–8 个内容资产验证英文质量、证据审核与发布节奏。

缺写作与渠道产能 → Agency

如内部无法安排固定写作工时，可按同一内容清单采购；要求先看样稿、确认渠道能力和内部审核依赖，再按明确范围启动。

第八周 → 用执行证据调整

内部能持续交付则继续自建；若卡在写作或分发，针对缺口采购对应服务。无需等八周就对长期 SEO 效果下结论。

待确认事项

  • 资源：选择路径，并指定 owner；自建需要写作工时，agency 也需要内部产品审核和工程上线支持。
  • 预算：批准试点资源上限；按修订后的 agency 包价、内部人力全成本与工具/媒体费形成可比较预算。
  • 范围与复盘：先做美国英文高意图问题，六个月观察增长；八周检查内容质量与执行节奏，决定继续或调整资源。
展开 SEO 与 GEO 两条服务线的具体思路与 KPI

Service line 01

SEO｜让潜在客户在 Google 搜得到

面向美国 / 英文 / Google 首期市场，搭建稳定的非品牌自然搜索入口。

为什么提供 SEO

在已完成的技术基础之上，下一步用页面和内容承接非品牌需求。围绕 Shopping API、Product Search API、MCP 接入和平台替代方案，补足页面主题、产品证据与操作示例，连接到试用和有效调用。

Agency 服务内容

  • 技术维护：复用已完成的基础优化，按发布节奏复查抓取、索引和页面性能；新增问题单独确认范围。
  • On-page SEO：优化首页、Pricing、Docs、Quickstart；新增 API、MCP、方案比较等高意图页面。
  • 内容 SEO：围绕 30 个核心词与 120 个衍生词规划内容；方案提出六个月约 36–42 个页面/内容资产。
  • 外链协同：先提供候选清单，双方审核质量和相关性后再执行，避免低质外链。

交付物与衡量

  • 关键词到 URL 映射、逐页内容简报、产品证据清单、月度选题与发布计划。
  • 首批页面与内容资产、结构化数据/内链/CTA 验收、GSC 与 GA4 追踪。
  • 每月复盘索引、非品牌曝光/点击、排名趋势及 Try API / MCP 转化。
  • 搜索流量、点击和排名目标先建立客户自有基线，再纳入双方确认的目标。

Service line 02

GEO｜让用户问 AI 时，品牌能进入答案

围绕国家/语言、模型和决策问题，提升可见度、引用与品牌信息准确性。

为什么提供 GEO

技术基础已完成后，下一阶段重点是增加 AI 可引用的优质内容：既覆盖用户的决策问题，又提供清楚、可核验的产品事实和使用证据。结合项目方持续运行的评估，检验哪些内容能让 CommerceAI 被正确理解、引用并进入推荐候选。

Agency 服务内容

  • Topic / Prompt 设计：参考 Google、Semrush、Keyword Planner 的需求与难度，再结合产品功能和人群决策模拟提问；评审建议关键词 KD < 50。
  • AI 可见度监测：钛动介绍其太极大模型与 TECHROS 监测工具，记录回答、提及和来源，提供相对可解释的监测数据。
  • 信源侦测：识别 AI 常引用的官方文档、社区、第三方与 PR 来源，作为寻找同类渠道的线索，不是可直接投放的名单。
  • 内容建设与可引用性：补齐产品事实、API/MCP 实测教程、对比矩阵、FAQ 与证据来源；以独立清晰的答案段落、适用边界和更新时间支持引用。技术项转为发布复查。

交付物与衡量

  • 复用项目方正在运行的 GEO 评估；先对齐平台、Prompt、采样频次与品牌识别口径，衔接 agency 的监测报告。
  • 纪要记录的售前样本为 8 个 Topic、40 个 Prompt、3 个模型 × 5 次，共 600 条回答；此为历史样本，优化后的现状应以最新复测为准。
  • 首期优先前 5 个 Topic（含 Shopping API / Product Search API），按 P0–P3 排序。
  • 输出可见度、引用、信息准确性、竞争偏好和商业指标五层漏斗。
  • 核心 KPI：目标问题中品牌被提及的比例；六个月提升目标应写入合同并定义模型、Prompt、重复次数、品牌变体和计分方式。
  • 流量与转化归因作为辅助指标；按市场、语言、模型分别报告。
